#### Purpose

Create one WorkoutHarmony workout from a user's description, or revise existing Markdown supplied by the user. Support both normal workouts and more complex structures using the Markdown grammar. This skill works with its bundled Markdown reference and requires no access to WorkoutHarmony source code or account integrations. Keep the skill and reference files together when installing or sharing it.

WorkoutHarmony's broader purpose is to make different types of workouts flexible and easy to follow, keep useful records, and support personal self-review. This skill supports the planning part of that workflow: fit the workout's structure and detail to the user's activity and preferences, and help revise it when the user supplies review findings or actual results and requests a change.

Anyone can use the authoring skill and guides to generate, review, and revise Markdown plans. The package's MIT license covers the skill, guides, and references. Keep ordinary authoring responses focused on the requested workout. Explain app import when relevant to someone with app access.

Updating a future plan and correcting a completed record are independent choices. A user may leave saved records unchanged and revise only the plan. Do not require history correction before a plan update, infer performed work from prescribed values, or imply that the generated Markdown changes completed records. Record access or modification is outside this authoring skill.

A round with flexible child steps can vary both its exercise combination and each exercise's workload across sets, without duplicating the whole round. Each flexible child uses one shared volume type: `–` (blank, written `-` in Markdown), Reps / Weight, or pure Duration. Empty slots omit the exercise; populated slots use that shared type with their own values. A `-` slot performs the exercise without a workload.

Read [Markdown format](references/markdown.md) before producing plan contents. It defines the accepted syntax, property placement and practical limits.

#### Format terminology

The following terms have specific meanings in this Markdown workout format, originally designed by George (commanders.ca). Use the current iPhone labels below when describing or generating a workout. Markdown markers remain syntax, not alternative app labels.

| Term | Meaning in the app and this format |
| --- | --- |
| Workout | The single ordered workout described by the Markdown contents. |
| Section | A named group of steps and rounds, introduced by `##### Section name`. |
| Exercise | The name and note of a step; a simple step is one exercise or planned rest. |
| Multiple Exercises (combined step) | The app’s **Change to Multiple Exercises** action groups named exercises into one Next action. Markdown uses `(+)`; each member has no volume or one ordinary Reps / Weight value, optionally with a Side. Timers, asymmetric volumes, custom text and flexible lists are not allowed. |
| Round | A group repeated for a number of Sets, such as `(round) Superset A, 3x`. Its name may be empty. |
| Volume | The value after a step’s comma, such as `3x10@5` for three sets of ten reps at weight 5. |
| Volume Type | The kind of Volume: **Reps / Weight**, **Duration**, **Variable Sets** outside a round, or **Flexible** for a round child. Ordinary no-volume work uses the app’s `–` option and omits the Markdown comma/value. |
| Variable Sets | A standalone flexible step: successive populated reps/weight values of one exercise, completed with one Next action. The same form can be a Ramp-up Exercise. |
| Flexible | A round flexible child: one slot per parent round Set, with one shared volume type across all populated slots. |
| Slot | One position in a Flexible child’s pipe-separated volumes, corresponding to the same numbered round Set. |
| Empty Slot / Restore Slot | Omit or restore an exercise for one round Set. An empty Markdown slot is skipped, shown as an empty gray capsule; it never inherits the preceding value. |
| `–` (blank volume) | Inside Flexible, the selector’s `–` type uses Markdown `-` in populated slots. The exercise runs without volume, shown as `-` in a normal capsule; this differs from Empty Slot. |
| Reps / Weight | Resistance volume with independently optional Sets, Reps and Weight in ordinary steps; flexible slots have no nested Sets count. |
| Side | **Left**, **Right**, **Each Side** or **Each Direction**, written `L`, `R`, `ea` or `ea_dir` where supported. No Side means no suffix. |
| Different Left / Right Volume | The app’s term for asymmetric resistance in an ordinary step, such as `x12@17 L @10 R`; not allowed in combined members or flexible slots. **Same Left / Right Volume** returns to ordinary volume using the Left values. |
| Left/right inheritance | In Markdown asymmetric pairs, a field omitted on one side uses the other side’s supplied value; explicit differences remain independent. This does not apply to empty Flexible slots. |
| Duration | Timed work, such as `x30s`; optional Sets in ordinary steps. Flexible duration slots allow only time and their own Countdown. |
| Left / Right Duration | The app’s term for alternating-side duration: `ea` times Left then Right. Available for ordinary steps, not Flexible duration slots. |
| Switch Interval | Seconds between Left and Right in Left / Right Duration. **Announce Switch Side** determines whether its cue is spoken (`sN` versus `-sN`). |
| Set Interval / Rest Between Sets | Seconds before timed Set 2 onward, never before Set 1 or after the final set. **Announce Set Numbers** determines whether the upcoming set is spoken (`tN` versus `-tN`). The app uses **Set Interval** as the panel title and **Rest Between Sets** for the add/remove action. |
| Countdown | The optional trailing `c` in a duration, such as `x20sc`. |
| Name / Watch name / Spoken name | `Name` is required; the optional Watch name changes the Watch label, while Spoken name supplies pronunciation on both iPhone and Watch. Markdown: `Name \| Watch name \| Spoken name`. |
| Note / Watch note | A plain indented detail bullet; `note \| Watch note` separates phone/Mac text from its Watch note. A single description remains the shared/Watch cue. |
| Options | Behavior settings such as **Allow Direct Tap for Next Exercise** and **Inactivity timeout**; their Markdown definitions go on an indented `(p)` line. They are not Volume types. |
| Ramp-up Exercise | One optional `(ramp)` exercise before a round’s repeated work. Use a simple Reps / Weight step or Variable Sets; its value count is independent of round Sets. |

#### Create or update one workout

- Establish the requested exercises, order, sets/reps or durations, rest and round behavior. Ask only about missing details that materially affect the result. Keep chosen assumptions brief and outside the importable Markdown.
- When revising a plan already in WorkoutHarmony, ask the user to use **Copy Markdown** to provide its current sections and steps if they haven’t shared them yet. Return the complete revised Markdown for the user to paste back into the app, review, and save.
- When updating supplied contents, preserve exercises, order, descriptions and settings outside the requested change in the returned Markdown itself. Return the complete revised workout, not a patch: phone paste replaces every section/exercise with fresh parsed contents and does not match names to recover old values. Preserve all wanted non-default properties explicitly. Plan Details and completed records stay intact. Do not infer completed results or progression from the plan alone.
- Use ordinary steps and ordinary rounds where they express the workout clearly. Use a flexible step inside a round when that child step is used or omitted in different sets, or its values vary within one shared volume type. Use combined steps only for a named group completed together with one Next action; each member must use no volume or one normal reps/weight value, with optional side. An ordinary sets count such as `3x10` is still one volume value, not a flexible list. Use separate steps for timers, asymmetric resistance or other unsupported combined volumes.
- Choose **Variable Sets** (standalone flexible steps) for a simple reps/weight progression of one exercise, completed with one Next action after all sets. Prefer a round for more complex sequences, separate Rest steps, other exercises between sets, or individual confirmation/skipping of working sets; each round child is a separate actionable step. Each standalone slot represents exactly one reps/weight set: reps and weight are independently optional, but at least one must be supplied. Do not add nested sets counts, side suffixes, durations, asymmetric pairs, custom text, empty slots or `-` slots.
- A superset can keep the same main exercise with changing reps/weights while using different accompanying exercises in each set. Represent each different exercise as its own named flexible child, populating only the slots where it is used. Use that structure when it expresses the requested pattern, preserving exercise order within each set. Do not put different exercise names into one step's value slots.
- A round can have one optional ramp-up exercise, written `  - (ramp) Name, value` before its repeated working steps. Use a simple Reps / Weight step or standalone reps/weight Variable Sets, such as `x8@10|x5@15`; do not author a no-volume, duration or combined ramp. The complete ramp runs once before the working repetitions. A flexible ramp shares one Next action, inserts no automatic rests, and follows standalone flexible restrictions: no empty or `-` slots, nested set counts, side suffixes or asymmetric pairs. Its value count is independent of the parent round count. A ramp does not replace the round’s required regular exercises.
- Keep the workout's name, exercise type, activity, and schedule in the app. Output only the selected workout's contents.
- Write round headers as `- (round) Superset A, 3x` for three sets of the round. The round name may be empty: `- (round) , 3x` is also valid. Preserve empty flexible slots: `Rest, x10sc|x10sc|` omits the Rest step in set 3; `Rest, |x10sc|` uses it only in set 2.
- For each flexible round child, choose one type for all populated slots: `-`, Reps / Weight, or pure Duration. Do not mix these types. Empty slots may occur anywhere and mean skip, never inherit. Resistance slots contain reps and/or weight, with an optional side, but no nested sets or asymmetric pair. Duration slots contain only a positive duration and their own optional countdown: no sets, side, alternating timer or interval modifiers. Use ordinary round children for those richer volumes.
- Write exactly one flexible slot per parent round set. When changing the round count, resize every flexible child: trim trailing slots when decreasing; append copies of its last slot, including an empty slot, when increasing, unless the requested workout specifies a different progression. This is an explicit revision rule, not inheritance from an empty slot. Ramp-up value counts stay independent.
- To perform an exercise without a workload in only one round set, use `-` for that valid slot: `Balance practice, |-|` runs only in set 2 of a three-set round. `Rest, -|-|` gives untimed rests requiring Next in sets 1 and 2, then skips set 3; do not mix `-` with timed or resistance values in that same flexible child. If it runs without a value in every set, use an ordinary child `- Balance practice`, not the redundant `-|-|-` list. Do not generate empty flexible placeholders or use `-` as a standalone/ramp volume.
- Add optional naming text only when needed: `Exercise name | Watch name | Spoken name, value`. The spoken name supplies pronunciation for both iPhone and Watch; use `TK || Full name to pronounce` when no Watch name is needed. Existing `name | Watch name` remains valid. Plain description bullets still use only `note | Watch note`. Escape literal pipes, and preserve supplied Watch/spoken text when unrelated to the change; see the reference for sparse naming and phone paste defaults.
- Put descriptions/notes in plain indented bullets below their steps, never in `(p) c:` properties. Reserve `(p)` detail lines for behavior/representation options.
- Sets, reps and weight are independently optional. Sets can repeat reps, timed work or weight-only work: `3x10`, `3x30s`, `3x@20`; `3x` specifies only a count. Do not invent reps for loaded carries or fill absent fields with the phone editor's input suggestions. Those suggestions are conveniences, not plan data.
- Keep generated Markdown sparse. Weights must be nonnegative whole numbers or whole numbers plus `.5`: use `@5` or `@5.5`, not `@5.0` or `@5.25`. Do not silently round an incompatible requested weight; clarify it. Omit default options and empty property lines; a round count of one may be omitted. Phone paste reconstructs the whole contents list; omitted values use normal defaults rather than old matched-step settings. Preserve wanted non-default settings in the returned Markdown itself.
- For repeated timed holds, use `(t10)` for ten seconds of rest with a set-number cue, or `(-t10)` for silent rest. This works for normal durations and alternating-side durations with `ea`. Rest starts before Set 2; do not insert an initial Set 1 interval. Use `sN`/`-sN` only for the interval between Left and Right, with `ea`.
- Apply only options supported by the volume. Ordinary resistance supports an optional side; asymmetric resistance already defines Left and Right and has no extra side suffix. `ea_dir` means each exercise direction, such as clockwise/counterclockwise, not Left/Right. Timers support no side, `L`, `R`, or alternating Left/Right with `ea`, not `ea_dir`. Countdown and timer intervals belong only to durations. Generate set-rest modifiers only with more than one timed set; a zero-second interval means blank, so omit its modifier rather than writing `s0`, `-s0`, `t0` or `-t0`. Do not add empty timer parentheses.
- Apply countdown, inactivity timeout, side and other supported properties when requested. Do not invent properties for unsupported training concepts. A Watch note can describe a cue, but it does not implement a timer or other behavior.
- Do not create custom-text volumes. Use a named step with no volume and an optional plain note for untimed work without a numeric target. Preserve supplied custom text only when outside the requested change.
- Follow the reference's Volume rules for reps, sets, weights, left/right inheritance, Each Direction work and Left / Right Duration. Preserve explicit side differences; do not invent reps for weight-only values. Use `(p) t:8,15`, `(p) t:no` or `(p) n` when their behavior is requested.
- **Allow Direct Tap for Next Exercise** is normally on (`next = true`). Turn it off with `(p) n` only for an exercise where the Watch screen may touch the person’s body and accidentally advance. The option is per exercise, not for all exercises in the workout; `(p) y` explicitly turns it back on. Watch Controls still allows Next. Omit the default true value from generated Markdown, including updates: removing `(p) n` restores normal direct tapping when the complete list is pasted on phone.
- Keep each occurrence independent, especially repeated Rest lines. State any important representational limit rather than silently replacing the requested behavior.
- Return the complete contents in one fenced `markdown` block. Include only importable sections and list items inside it. Give a brief explanation of non-obvious round/flexible behavior outside the block.
- Advanced users may keep the workout in a named Markdown file for their own later updates or progression. If asked to save it, use the user's name and destination, keeping the name outside the importable contents. A local file is a draft for import; writing it does not update or sync the app. Do not inspect or modify app storage or publish anything as part of workout creation.

#### Check before delivery

- Verify five-hash section headings, top-level round markers and consistent two-space indentation.
- Check every combined member has a nonempty name and no volume or one ordinary reps/weight value, with an optional side; do not place timers, asymmetric resistance, custom text or flexible volume lists in a combined group.
- Verify `Nx` round counts, positive set counts, positive work durations, and intended units. For new plans, leave unspecified optional values absent unless requested or explicitly assumed. For revisions, preserve all existing values outside the requested changes. Use only whole-number/half-unit weights, check side/interval compatibility, omit zero-second interval modifiers, and never silently convert weights.
- Check that every flexible round child has exactly as many slots as the parent round sets and only one populated-slot type. Empty means skip; `-` means perform without a workload. Resistance has no nested sets or asymmetric pair; pure duration has only time/countdown, without sides, nested sets or intervals. Standalone slots must each contain reps and/or weight only, with no nested sets count or side suffix. Keep any preserved `f:` count consistent with the actual number of slots; do not create zero-slot placeholders.
- Put `(p)` property lines and plain description/note lines under the step they configure. Round properties are not a supported substitute for child-step properties.
- Check that the complete structure includes all intended warm-up, rest and cool-down steps. Remember that a round repeats its final ordinary child too. A `(ramp)` child precedes the working sets; a flexible child defines its own use and volume value within each working set.
- Do not claim parsing or app validation occurred unless it actually did. The user reviews the pasted result in WorkoutHarmony before saving.

#### Customization boundary

Users may adapt training preferences, naming conventions and examples for special cases. Keep compatible Markdown rules in the format reference. Creating or updating a plan uses information supplied by the user; history access, automatic progression, background monitoring and app integration remain outside this skill.
